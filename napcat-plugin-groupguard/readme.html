System Architecture Report

NapCat 群管插件采用“插件生命周期 + 命令路由 + 被动事件处理 + SQLite 持久化 + WebUI 管理面板”组合架构。核心控制点集中在 src/index.ts、src/commands.ts、src/state.ts、src/storage_adapter.ts。

Plugin Entry Command Router Event-Driven SQLite Persistence WebUI Admin Panel

A. System Overview

Startup Sequence

  1. NapCat 加载插件并调用 plugin_init。
  2. 初始化 pluginState 上下文、日志、适配器与运行配置。
  3. 加载主配置文件并执行全局/分群配置归一化。
  4. 执行历史目录迁移：旧 JSON 分群配置 → data/groups/* → SQLite。
  5. 初始化 storageAdapter、initDB、授权、邀请服务、自撤回恢复。
  6. 注册 WebUI 页面与 HTTP 路由。
  7. 拉取机器人登录信息并记录 botId。

Main Entry Files

  • src/index.ts：插件入口、生命周期、HTTP 路由、消息/事件主调度。
  • src/state.ts：全局状态、发送队列、缓存、权限判断、运行指标。
  • src/commands.ts：命令路由总入口。
  • src/config.ts：默认配置与归一化规则。
  • src/storage_adapter.ts：SQLite 与 JSON 迁移桥接层。

Main Runtime Flow

阶段 入口 动作 输出
初始化 plugin_init 加载配置、初始化存储、注册路由、启动恢复任务 可运行插件实例
消息处理 plugin_onmessage 授权检查 → 路由命令/问答/风控/统计/缓存 群消息动作、私聊动作、持久化更新

B. Architecture Layers

分层方式以职责边界为主：表现层负责输入输出，业务层负责规则与流程，数据层负责持久化与迁移。
层级 模块 职责 典型文件
表现层 NapCat 插件入口、消息事件入口、WebUI 页面、HTTP 路由 接收消息/通知/请求，提供配置面板与管理 API，组织输出格式 src/index.ts、webui/config.html、webui/assets/command_manual.json
业务层 命令模块、服务模块、授权、验证、回复模板、动作队列 命令解析、风控判断、积分玩法、战绩查询、入群校验、执行节流与恢复 src/commands/*、src/services/*、src/auth.ts、src/verify.ts、src/join_verifier.ts
数据层 仓储、缓存、SQLite 适配、配置持久化 存储群配置、QA、签到、邀请、活跃、警告、自撤回任务 src/storage_adapter.ts、src/db.ts、src/repositories/groupguard_repository.ts

表现层模块归属

  • src/index.ts：生命周期与 HTTP 路由入口。
  • webui/config.html：统一控制台，分全局/分群面板。
  • src/commands/modules/*：命令匹配器与域级 handler 入口。

业务层模块归属

  • interaction_service.ts：互动、签到、抽奖、战绩、视频。
  • moderation_service.ts：禁言、踢出、头衔、名片锁。
  • risk_service.ts：风控策略与安全开关。
  • action_queue_service.ts：动作排队、重试、恢复。

C. Data Flow

群消息 → plugin_onmessage → handleCommand / handleQA / 风控链路 → storageAdapter / NapCat API
输入源：OneBot 消息事件。处理路径覆盖授权校验、黑白名单、命令执行、问答、刷屏检测、消息缓存、活跃统计与表情回应。
群通知/请求 → plugin_onevent → GroupJoinVerifier / verify / sendWelcomeMessage / enqueueKickAction
输入源：入群申请、入群通知、撤回通知、退群通知。输出为审核动作、欢迎消息、私聊验证、拉黑或恢复任务。
WebUI → /config /runtime /group-config/* → normalizePluginConfig / healGroupSettings → saveConfig / SQLite
输入源：浏览器管理面板。输出为全局配置、分群配置、导入导出文件与运行态数据。
外部接口 → interaction_service.ts → fetch/fetchJsonWithTimeout → 输出为文本/转发/图片/卡片
输入源：战绩接口、封号接口、视频接口。输出为群消息内容，失败时返回降级提示。

Storage Location

  • 主配置：NapCat 配置文件路径对应的插件配置。
  • SQLite：data/groupguard.db。
  • 迁移来源：旧 groups/*.json 与 data/groups/*/*.json。
  • 内存缓存：state.ts 中的 sessions、msgCache、spamCache、adminCache、queue 状态。

Import / Export Flow

  • 全局配置：WebUI 通过 GET/POST /config 读取与保存。
  • 分群导出：GET /group-config/export 输出分群设置与修复记录。
  • 分群导入：POST /group-config/import 支持 overwrite / merge。
  • 导入自检：去重数组、修复 QA 结构、统一 useGlobal=false。
  • 历史迁移：启动时执行 JSON → SQLite 迁移并打标记。

D. Critical Path

Core Call Chains

  • 命令链：plugin_onmessage → handleCommand → registry → modules/* → services/* → pluginState/actions/storage。
  • 验证链：plugin_onevent(group_increase/request) → GroupJoinVerifier / createVerifySession → handleVerifyAnswer → 踢出或欢迎。
  • 撤回恢复链：state.scheduleSelfRecall → repository/db → action_queue_service recovery tick → safeRecall。
  • WebUI 配置链：config.html → /config → normalizePluginConfig → saveConfig → storageAdapter.saveGroupConfig。

Single Point of Failure

  • HighpluginState：配置、权限、发送、缓存全部集中依赖。
  • HighstorageAdapter / groupguard.db：持久化主入口失效会影响统计、配置与恢复任务。
  • Highsrc/index.ts：生命周期、路由与消息事件总入口高度集中。
  • Medium本地/外部接口：战绩、封号、视频查询依赖外部可用性。

High-Risk Modules

模块 风险等级 原因 影响
src/index.ts High 入口聚合过多：初始化、路由、消息、事件、迁移 变更风险大，回归范围广
src/state.ts High 状态与发送控制集中，承担缓存、权限、队列、日志 运行时异常会影响全局功能
src/services/action_queue_service.ts High 动作排队、重试、恢复逻辑复杂，涉及时序与幂等 禁言/踢出/撤回动作易出现重复或丢失
src/storage_adapter.ts Medium 同时承担 schema、迁移、读写适配 存储变更易影响历史数据兼容
src/services/interaction_service.ts Medium 聚合功能较多：签到、抽奖、战绩、视频、封号查询 接口波动或改动易产生联动回归

E. Legacy / Redundant Modules

对象 状态 现象 建议
旧 JSON 分群结构 Legacy 启动时仍保留 groups/*.json 与 data/groups/* 迁移逻辑 迁移稳定后可拆出独立 migration 脚本，缩减 index.ts 负担
双份命令手册 JSON Redundant webui/command_manual.json 与 webui/assets/command_manual.json 存在重复内容 统一单一来源，避免文档漂移
多份用户/主人手册 HTML/MD Redundant README、USER_MANUAL、USER_MANUAL1、OWNER_MANUAL、DEVELOPER_MANUAL 多版本并存 拆分“对外说明”与“内部设计”两套文档，减少重复维护
db.ts + repository + storageAdapter Overlap 数据访问链较长，db.ts 与 groupguard_repository.ts 包装层存在重叠 可合并为统一 repository 层，减少跳转层级
src/index.ts 超大入口 Optimization Target 既做生命周期，又做路由、迁移、事件处理 拆分为 bootstrap、http-routes、message-pipeline、event-pipeline

Core Service Cluster

  • Command Cluster：registry + modules + services。
  • Runtime Cluster：state + action queue + guard service。
  • Storage Cluster：storageAdapter + db + repository。
  • WebUI Cluster：config.html + HTTP routes。

Audit Focus

  • 入口聚合度高，适合按生命周期拆分。
  • 动作队列与撤回恢复是时序敏感区域。
  • 存储链路存在多层包装，适合压缩层次。
  • 文档与命令手册存在重复维护面。
